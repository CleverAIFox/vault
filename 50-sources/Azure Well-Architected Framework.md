# Azure Well-Architected Framework

> 한 줄 요약: 마이크로소프트 Azure의 워크로드 설계 기준. 안정성·보안·비용 최적화·운영 우수성·성능 효율 다섯 기둥으로 점검한다.

## 출처
- 저자·기관: Microsoft, Microsoft Learn
- 날짜: 2026-09-11 갱신
- 링크: https://learn.microsoft.com/en-us/azure/well-architected/

## 핵심 세 줄
1. 다섯 기둥으로 설계를 점검한다.
2. 기둥 원칙 → 기술 설계 영역 → 검토 도구 순서로 쓴다.
3. AI·SaaS·미션 크리티컬 같은 워크로드별 지침이 따로 있다.

## 절별 요약
- 안정성: 중복과 회복력으로 가동·복구 목표를 지킨다.
- 보안: 기밀성과 데이터 무결성을 지켜 공격을 막는다.
- 비용 최적화: 조직·아키텍처·전술 수준에서 예산 안에 머문다.
- 운영 우수성: 관측성과 자동화로 운영 문제를 줄인다.
- 성능 효율: 수평 확장과 사전 테스트로 수요 변화에 맞춘다.
- 그 밖에: 서비스별 가이드, Azure 아키텍처 검토 평가 도구, 학습 경로.

## 내 생각
- AWS Well-Architected(6기둥)와 비교하면 지속 가능성 기둥이 없고 워크로드 지침으로 뺐다. 두 노트를 링크해 클라우드 공통 원칙을 뽑는다.
