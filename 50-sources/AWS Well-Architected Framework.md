# AWS Well-Architected Framework

> 한 줄 요약: 클라우드 워크로드를 여섯 기둥(운영 우수성·보안·안정성·성능 효율·비용 최적화·지속 가능성)으로 점검하는 AWS의 설계 기준.

## 출처
- 저자·기관: Amazon Web Services
- 날짜: 상시 개정되는 문서(페이지에 날짜 없음)
- 링크: https://docs.aws.amazon.com/wellarchitected/latest/framework/

## 핵심 세 줄
1. 설계를 여섯 기둥으로 나눠 질문하고 점검한다.
2. 기둥은 운영 우수성, 보안, 안정성, 성능 효율, 비용 최적화, 지속 가능성이다.
3. 공통 설계 원칙 여섯 개가 기둥 전체를 관통한다.

## 절별 요약
- 운영 우수성: 시스템을 돌리고 지켜보며 절차를 계속 개선한다.
- 보안: 정보·시스템·자산을 지키면서 사업 가치를 낸다.
- 안정성: 의도한 기능을 꾸준히 해내고 장애에서 회복한다.
- 성능 효율: 자원을 효율적으로 쓰고 수요 변화에 맞춘다.
- 비용 최적화: 불필요한 비용을 피하고 쓴 만큼 가치를 얻는다.
- 지속 가능성: 워크로드의 환경 영향을 줄인다.
- 공통 원칙: 용량을 추측하지 않기, 실제 규모로 테스트, 실험을 염두에 둔 자동화, 진화하는 아키텍처, 데이터로 결정, 게임 데이로 개선.

## 내 생각
- AWS 자격증(CLF·DEA) 시험 범위와 가장 많이 겹친다. 여기서 정리하면 시험 공부와 볼트가 한 번에 된다.
- Maat를 AWS에 올릴 때 설계 검토 체크리스트로 그대로 쓴다.
