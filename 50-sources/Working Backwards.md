# Working Backwards

> 한 줄 요약: 제품을 만들기 전에 출시 보도자료와 FAQ부터 써서, 고객에서 거꾸로 필요한 기술을 정하는 아마존의 기획 방식.

## 출처
- 저자·기관: Werner Vogels(아마존 CTO), All Things Distributed 블로그
- 날짜: 2006-11-01
- 링크: https://www.allthingsdistributed.com/2006/11/working_backwards.html

## 핵심 세 줄
1. 고객에서 출발해 목표에 필요한 최소한의 기술까지 거꾸로 내려간다.
2. 보도자료 → FAQ → 고객 경험 → 사용자 설명서 순서로 문서를 먼저 쓴다.
3. 문서가 무엇을 만들지 분명히 하고, 팀의 공통 비전이자 다른 팀에 설명하는 자료가 된다.

## 절별 요약
- 보도자료: 제품이 무엇을 하고 왜 있는지, 바깥 사람 눈으로 짧게 쓴다.
- FAQ: 보도자료를 돌려 보며 나온 질문과 사용자 입장의 질문에 답한다.
- 고객 경험: 화면이면 화면마다 목업, 웹 서비스면 코드 예시가 든 사용 사례를 쓴다.
- 사용자 설명서: 개념·사용법·레퍼런스로 나눠 쓴다. 사용자 유형이 여럿이면 설명서도 여럿.
- 원칙: 서비스 구조가 곧 조직 구조, 작은 팀과 강한 주인 의식, 필요한 것만 만든다.

## 내 생각
- Maat 기획서(pitch)가 사실상 PR/FAQ다. 형식을 이 글에 맞추면 기획의 기준이 생긴다.
- "필요한 것만 만든다"는 Fire-Lane·Maat의 과설계 교훈과 정확히 같은 말이다.
