# Google Code Review Guidelines

> 한 줄 요약: 구글이 공개한 코드 리뷰 가이드. 완벽하지 않아도 코드 건강을 확실히 개선하면 승인한다는 원칙이 핵심이다.

## 출처
- 저자·기관: Google, eng-practices 저장소
- 날짜: 상시 개정(CC-BY 3.0)
- 링크: https://google.github.io/eng-practices/

## 핵심 세 줄
1. 리뷰어 가이드와 변경 작성자 가이드, 두 묶음으로 나뉜다.
2. 가장 높은 원칙: 변경이 시스템의 코드 건강을 확실히 개선하면 완벽하지 않아도 승인한다.
3. CL(변경 하나)과 LGTM(승인) 같은 구글 용어를 쓴다.

## 절별 요약
- 리뷰어 가이드: 코드 리뷰의 기준, 무엇을 볼지, 리뷰 순서, 속도, 코멘트 쓰는 법, 반발 다루기.
- 작성자 가이드: 좋은 변경 설명 쓰기, 작은 변경으로 나누기, 리뷰 코멘트에 대응하기.
- CL은 다른 곳의 PR(풀 리퀘스트)·패치와 같은 말이다.

## 내 생각
- Maat PR 템플릿과 리뷰 규칙의 근거로 쓴다. 혼자 하는 프로젝트라도 AI 리뷰어에게 이 기준을 그대로 준다.
- "작은 변경" 원칙은 Conventional Commits·트렁크 기반 개발과 맞물린다.
