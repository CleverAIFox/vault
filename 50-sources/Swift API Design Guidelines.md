# Swift API Design Guidelines

> 한 줄 요약: Swift 언어의 API 설계 지침. 가장 중요한 목표는 "사용하는 지점에서 명확한 것"이다.

## 출처
- 저자·기관: Swift 프로젝트(애플 주도 오픈소스), swift.org
- 날짜: 상시 개정
- 링크: https://www.swift.org/documentation/api-design-guidelines/

## 핵심 세 줄
1. 사용하는 지점의 명확성이 가장 중요한 목표다.
2. 짧은 것보다 명확한 것이 중요하다.
3. API 기능을 쉽게 설명하기 어렵다면 API를 잘못 설계한 것일 수 있다.

## 절별 요약
- 기본: 사용 지점의 명확성, 간결함보다 명확함, 모든 선언에 문서 주석.
- 이름 짓기: 쓰임새가 분명하게, 유창하게 읽히게, 용어를 잘 고르기.
- 관례: 일반 관례, 매개변수, 인자 레이블.
- 특별 지침: 타입 등 특수한 경우.

## 내 생각
- 언어는 Swift지만 원칙은 Python·TypeScript에도 그대로 통한다. Maat의 함수·API 이름 규칙의 근거로 쓴다.
- "설명하기 어려우면 설계가 틀렸다"는 기준은 AI 에이전트에게 주는 리뷰 규칙으로도 좋다.
